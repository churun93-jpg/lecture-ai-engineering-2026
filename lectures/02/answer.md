## 宿題

- 取り組んだレベル：基礎
- 変えた設定やデータ：
  - `CONFIG` の `num_train_epochs` を元の `20`（40ステップ）から **`10`（20ステップ）** に変更し、セッションを再起動して再学習・評価を行った（その他の設定は同一）。
- 結果（比較表や数字）：

  | 項目 | 元の設定（`num_train_epochs: 20`） | 変更後（`num_train_epochs: 10`） |
  | --- | --- | --- |
  | ステップ数 | 40 ステップ | 20 ステップ |
  | 学習時間 | 243 秒 | 122 秒 |
  | Step 10 Training Loss | 1.567629 | 1.565419 |
  | 最終 Training Loss | 0.013946（Step 40） | 0.098316（Step 20） |
  | 学習前 `format_rate` / `content_rate` | 0.095 / 0.000 | 0.095 / 0.000 |
  | 学習後 `format_rate` | 1.000（21/21） | 1.000（21/21） |
  | 学習後 `content_rate` | 0.905（19/21） | 0.905（19/21） |
  | 退行（`regressed`） | なし（`[]`） | なし（`[]`） |

  - エポック数を半分の `10` に減らしたところ、学習時間は `243秒 → 122秒` とちょうど半分になり、最終 Loss は `0.013946` に対して `0.098316` とまだ下がりきる前の値となった。
  - それにもかかわらず、テスト21問における `format_rate`（1.0）と `content_rate`（0.905）は20エポック時と全く同じスコアに到達した。
  - ただし、セクション6の「担当教員の名前は何ですか」に対する出力文面を見ると、20エポックでは `「この FAQ には記載がありません。運営に確認が必要です。」` だったのに対し、10エポックでは `「この FAQ には記載がありません。必ずに確認が必要です。」` と定型文の一部（「運営に」→「必ずに」）にわずかな崩れが見られた。
- ファインチューニングが向く場面・向かない場面についての考察：
  - **向く場面**：10エポック（約2分・14件のデータ）の学習でも `format_rate` が 9.5% から 100% に向上したように、プロンプトだけでは安定しない「JSONなどの厳密な出力形式の遵守」や「特定の口調・定型文スタイルへの統一」を小さなモデルに身につけさせる場面に非常に向いている。また、まずは形式が身につく最小限のエポック数（10エポック）で素早く試し、定型文の細部まで安定させたい場合にエポック数を増やす（20エポック）といった調整が有効だと分かった。
  - **向かない場面**：20エポックまで学習させて Loss を `0.0139` まで下げても、「FAQに書かれていない事実（成績発表日、事前予約の有無、最終課題の締切）を聞かれたときに知ったかぶりをせず確認を求める」という事実性の判断ミスは解消しなかった。個別具体的な知識の追加や、頻繁に更新される情報・根拠の有無の厳密な判定をファインチューニングだけで解決しようとするのは不向きであり、検索（RAG・ツール利用）やルールベースの検証と組み合わせる必要がある。
